### 0:00 – 1:00 痛点：一个塑料袋里的 7 种药

> 各位评委老师好，我是守药人团队的路演人。`（停）`
> 我先给一个真实的画面：一位 78 岁的农村老人，同时吃 7 种药。
> 县医院开的华法林；听邻居说能防血栓，自己加的阿司匹林；膝盖疼，从村卫生室买的布洛芬；还有子女买的钙片。
> 每一种药，单独看都没问题。`（停）`
> 但华法林 + 阿司匹林 + 布洛芬叠在一起，消化道出血风险升高 2 到 3 倍——这三条规则就写在我们仓库的 `data/interactions.json` 里。
> 而村卫生室，通常只有 1 到 2 名村医，既看病又随访。基层几乎没有临床药师。`（停）`
> 所以真正的问题不是"缺一个查药的小程序"，而是——**这袋子药，谁来统账？**
> 我们的答案：守药人，一个面向基层医疗的多模态用药安全 Agent。

### 3:30 – 6:00 技术纵深：七步流水线、双引擎、混合检索

> 拆开讲三层。`（停）`
>
> **第一层，Agent。** 运行时在 `lib/agent/runtime.ts`，一条环路：输入安全审查 → 规划 → 工具编排 → 证据锚定 → 生成 → 输出守门 → 落盘。`（停）`
> 规划是**双引擎**：有 Key 时，让大模型输出结构化 JSON 计划——我们在 Prompt 里硬约束"必须包含 `check_interaction` 与 `search_kb`、检验异常必须含 `lab_assess`、描述危险症状必须含 `make_referral`"；没有 Key、断网、超时、解析失败，就落回确定性规则引擎，7 步固定流水线。`（停）`
> 关键在最后一句：**两个引擎共用同一套工具、检索和安全管线，所以产品行为契约不变。** 演示永不空白。`（停）`
>
> **第二层，工具。** 8 个工具全部是纯函数、零自然语言生成——避免"用模型判断模型"的循环。`lab_assess` 里把临床知识写成确定性分支：二甲双胍 eGFR 小于 30 停用、30 到 44 减量；格列本脲 65 岁以上按 Beers 清单建议避免；INR 大于 3 与大于等于 5 分两档；利尿剂 + ACEI + NSAID 的"三联打击"；血钾 5.0 与 5.5 两档；辛伐他汀 + 克拉霉素……一共 19 个发现点。`（停）`
> 为什么要确定性？因为剂量和停药这类判断，不允许"差不多"。`（停）`
>
> **第三层，RAG。** 双路召回：BM25，k1 取 1.5、b 取 0.75；加一路 384 维本地哈希向量——FNV-1a 哈希加正负号累加，也就是 signed hashing trick，再 L2 归一化。两路用 RRF 融合，k 取 60，最后加术语重排。`（停）`
> 融合公式是 0.5 乘 BM25 加 0.35 乘向量加 0.15 乘 RRF 加重排加分。为什么保留 0.5 的权重给 BM25？因为在医疗检索里，**术语精确命中比语义漂移更可信**。`（停）`
> 还有一步别人常漏：**证据锚定**。高风险发现如果没被检索命中，运行时会拿它的证据文档 id 去定向取证，补进证据链——不靠运气。`（停）`
> 检索效果我们做了量化：14 条带标准答案的探针，跑 `npm run eval:rag`，结果是 **Hit@1 是 0.714、Hit@3 是 0.929、MRR 是 0.836**。也就是说 14 条里 13 条进了前三。唯一掉到第 5 位的是"格列本脲 老年人 低血糖"，我们把这个短板也写进文档了。`（停）`
> 最后是置信度：0.35 打底，加前三条证据均分乘 0.3，加引用覆盖率乘 0.2，有发现再加 0.08，出现非法引用扣 0.1，截断在 0.2 到 0.96 之间。`（停）`

## 二、评委高频提问 Q&A（22 问）

> 每个回答 80–160 字，全部带文件或命令证据。回答时"先结论、再证据、最后一句话收"。

**Q1 为什么不用向量数据库（Milvus / pgvector / Chroma）？**
因为规模不够。知识库 17 篇文档、59 个分块（`lib/rag/index.ts:104-129` 一次性建索引后在进程内缓存），内存检索是毫秒级。引入向量库要多一个服务、多一个故障点，比赛现场断网或容器起不来就翻车。我们的索引结构是 `tf + len + Float32Array(384)`，换真实 embedding 只需替换 `lib/rag/embed.ts` 的 `embed()`，检索层零改动。

**Q2 哈希向量不是"假 RAG"吗？没有语义。**
它确实不是训练出来的语义空间，我们不宣称它是。它的作用是给 BM25 补一路"亚词级"近似召回：FNV-1a 加 signed hashing trick 再加长度加权（`lib/rag/embed.ts:18-50`），对"拜阿司匹灵 / 阿司匹林"这类变体和中文二元组有效。而医疗检索真正要靠的是术语精确命中，所以最终分里 BM25 占 0.5、向量只占 0.35（`lib/rag/index.ts:202`）。它是可解释的召回增强，不是语义理解。

**Q3 规则引擎算不算 AI？那不就是 if-else 吗？**
`lib/tools/index.ts` 是 if-else，但我们不把它当 AI 卖。AI 部分在 `lib/agent/runtime.ts`：规划（LLM 输出结构化 JSON 计划）、工具编排、证据锚定、生成、引用校验。规则引擎的作用是**确定性内核 + 兜底基线**：模型可以用它当"计算器"，但停药、减量这类判断由确定性代码下结论，避免"用模型判断模型"。这也是我们敢在医疗场景落地的原因。

**Q4 怎么防止幻觉？**
四层。一，证据约束：Prompt 要求每条结论带 `[n]`，`buildAnswerPrompt` 把工具结果和证据片段一起注入（`lib/llm/prompts.ts:99-118`）。二，引用校验：`verifyCitations` 检查 `[n]` 是否指向真实片段，非法编号进审计并扣置信度（`lib/rag/index.ts:231-246`、`runtime.ts:571-578`）。三，输出守门：诊断断言、绝对化、无引用剂量会被改写或加限定（`lib/safety/index.ts:124-180`）。四，无证据就降级为保守回答。

**Q5 医疗合规与责任边界怎么划？**
产品定位是"临床药师助手的用药安全审查"，不是诊断、不是处方。系统提示层硬约束：不做诊断、剂量只给方向、具体数值写"由执业医师核定"（`lib/llm/prompts.ts:17-30`）。输出层再拦一道：出现"确诊为""一定是"改写为"可能涉及"（`lib/safety/index.ts:128-146`）。每次运行写 JSONL 审计 + 完整轨迹（`lib/safety/index.ts:203-211`），出问题可回溯到具体规则、具体证据。责任边界是"辅助 + 可追溯"。

**Q6 数据来源与真实性？**
三层来源：药品信息按公开说明书整理（`data/drugs.json` 29 条，含别名、肾损提示、老年注意、监测项）；相互作用按机制与说明书禁忌整理（`data/interactions.json` 21 条，每条带机制、处置、证据 docId）；老年用药按 Beers 标准（`data/kb/kb-beers-elderly.md`）。患者全部虚构（`data/patients.json`），页面上标注"演示数据 · 非临床依据"（`app/layout.tsx:31`）。我们不说它是临床可用的，它是可验证的工程原型。

**Q7 和市面上的"用药助手 App"差在哪？**
三点。一，它们给结论，我们给依据：`[n]` 可点、四项打分可见、`/trace/[runId]` 可回放整条链路。二，它们查"两两相互作用"，我们做"检验指标分层 + 用药重整 + 随访 + 转诊 + 家属通知"的闭环，8 个工具（`lib/tools/index.ts:638-647`）。三，它们面向患者自助，我们面向村医 + 家属协同，输出是能直接粘贴到微信的通知（`notify_family`）。

**Q8 大模型挂了怎么办？现场断网呢？**
三层降级，全部有代码路径。规划失败：`runtime.ts:434-441` 捕获后 `mode='mock'` 并推 `note` 事件提示"已自动降级，后续流程不受影响"；生成失败：`runtime.ts:533-541` 用规则引擎合成同结构答案；空回答（少于 40 字）也判失败（`runtime.ts:532`）。未配 Key 时 `getLlmConfig().enabled` 直接为 false（`lib/llm/provider.ts:62`），整条链路走本地。演示永不空白。

**Q9 MCP 到底做了什么？有什么实际价值？**
把 8 个工具中的 5 个（`list_patients`、`check_interaction`、`lab_assess`、`search_kb`、`build_med_plan`）外化成标准 MCP 能力（`mcp/server.mjs:34-88`），stdio 传输，任何支持 MCP 的客户端都能调用。关键是架构：协议层在 `mcp/server.mjs`，实现层通过 HTTP 桥打到 `app/api/mcp/route.ts`，`tool.run()` 只有一份（`route.ts:43`）。所以端内 Agent 和外部 Agent 行为完全一致，不会出现"两套实现两套结论"。

**Q10 性能怎么样？首屏会不会很慢？**
实测数据说话：规则引擎下一次完整运行 **1.1–2.1 秒**（`logs/runs/*.json` 四次记录：1079 / 1545 / 2047 / 2060 ms），其中 6 次工具调用多为 0–5 ms，只有检索是 6–88 ms。首屏零阻塞请求：落地页与诊台都是服务端组件，4 位患者数据包一次下发（`app/console/page.tsx:14-17`），切患者不重新请求。前端无重型依赖：自研 128 行 Markdown 渲染器、手写 SVG 图谱、原生 `ReadableStream` SSE（`app/api/chat/route.ts:35-58`）。

**Q11 怎么证明检索有效？别只说"感觉准"。**
有可复现的量化脚本：`npm run eval:rag`（`scripts/eval-retrieval.mjs`）。14 条带标准答案的探针（如"华法林 布洛芬 出血 能一起吃吗"→ `kb-nsaid-anticoag`）打 `POST /api/kb/search`，与线上走同一条 `searchKb()` 路径。实测输出：**Hit@1 = 10/14 = 0.714，Hit@3 = 13/14 = 0.929，MRR = 0.836**。唯一未进前三的是"格列本脲 老年人 低血糖"（期望 `kb-beers-elderly`，实际第 5 位），原因是我们把它也写进了糖尿病文档，属于文档边界问题，已列入改进项。

**Q12 冷启动怎么做？村医凭什么用？**
冷启动不靠 C 端拉新，靠"已有的名单"。村卫生室本来就有慢病随访名单和老年人体检数据，我们的输入就是这份名单 + 一次药盒拍照。工具层不依赖任何外部服务即可运行（无 Key 也能跑完整流水线），所以一个乡镇卫生院就能试点。第一步只做一件事：把随访名单里"5 种药以上 + eGFR 低于 60 + 在用抗凝"的人筛出来，做一次用药重整，产出转诊单和家属通知。

**Q13 商业模式？谁付钱？**
三层。基础层：乡镇卫生院/村卫生室按点位年费订阅随访工具；中间层：县域医共体按"用药重整报告份数"结算，走医保外的健康管理服务包；平台层：把工具链通过 MCP 嵌进既有 HIS 与健康管理平台，按调用量或授权收费。成本侧的关键优势是无 Key 可用——没有大模型预算的机构也能上线，边际成本接近零。

**Q14 隐私怎么保证？患者数据会不会上传？**
数据不出机器。知识库与患者数据都是随仓库分发的本地文件（`lib/data.ts` 顶部注释与 `readJson`），推理在本机完成；PII 在进入模型前就脱敏，手机号、身份证、银行卡、邮箱四类正则掩码（`lib/safety/index.ts:20-59`），并且前端会显示"已自动脱敏个人信息"的安全标记。轨迹和审计只写本地 `logs/`（`lib/agent/store.ts:13`、`lib/safety/index.ts:186`）。

**Q15 多模态是不是只是调了个 API？**
调用只是第一步，我们在两头都加了工程。入口：图片限制 4MB、转 base64、走 `/api/vision`（`components/console/ChatPanel.tsx:105-139`）。关键是识别之后的**名称归一化**：模型常把"拜阿司匹灵""芬必得"写成各种变体，必须用 `findDrug()` / `extractDrugs()` 映射回本地 `drugId` 才能参与风险计算（`app/api/vision/route.ts:60-82`），匹配不上的明确标"未匹配，需人工确认"。没有 Key 时返回演示结果并显式标注 `provider=mock`，绝不伪装成真实识别。

**Q16 为什么不用 LangChain / LlamaIndex？**
成本高于收益。我们的环路是固定 7 步、工具 8 个、状态机很窄（`lib/types.ts:227-247` 定义 12 种 SSE 事件）。用框架会带来三件事：抽象层不可解释、流式事件要二次封装、依赖体积和版本风险。手写之后，`runtime.ts` 一共 630 行，从输入审查到落盘每一段都能当场指给评委看。框架擅长的是大规模工具集与复杂编排，我们不在那个区间。

**Q17 TypeScript 严格模式怎么落地的？不小心还是会有 any。**
`tsconfig.json` 开了 `"strict": true`，`npm run typecheck` 就是 `tsc --noEmit`，当前仓库跑通为 0 错误。落地靠三条纪律：一，全链路共用一套类型（`lib/types.ts` 定义 `AgentRun / SseEvent / KbHit / SafetyReport`），从 SSE 事件到 UI 渲染到审计落盘同一套结构；二，外部输入全部走防御式解析——LLM 计划解析失败就回退（`runtime.ts:127-153`），工具参数用 `Record<string, unknown>` 加运行时收窄；三，未知工具直接跳过并记录，不用 `any` 混过去。

**Q18 如果我当场给一个刁钻病例，你们的系统会不会崩？**
不会崩，但可能"不够聪明"——这两件事要分开说。不会崩：患者不在库里返回 `PATIENT_NOT_FOUND` 事件而不是白屏（`runtime.ts:400-404`）；问题超过 1000 字直接 400（`app/api/chat/route.ts:30-32`）；工具异常被 catch 成 `status:'error'` 事件继续跑完（`runtime.ts:234-247`）。不够聪明的地方我们承认：规则库只覆盖 29 种药、21 条规则，超出的组合会明确说"现有资料不足以判断，建议就医确认"，而不是编。欢迎您出一个病例，我们现在就跑。

**Q19 8 个工具是不是把 Agent 的自主性限制死了？**
不是，工具是"能力边界"，不是"执行路径"。LLM 引擎下，规划由模型自己出：它决定调哪些工具、顺序、参数，我们只做三件事——工具白名单校验、步数上限、强制补一步安全审查（`runtime.ts:140-148`，防止模型"忘记"守门）。规则引擎那 7 步是兜底基线，不是唯一路径。换句话说：有模型时它是自主 Agent，没模型时它是可审计的确定性流水线，同一套工具两种用法。

**Q20 一次运行要花多少 token？成本可控吗？**
规划一次非流式（`max_tokens` 700，`response_format` 用 json_object），生成一次流式（`max_tokens` 1600），`stream_options` 打开 `include_usage` 把真实用量回传（`lib/llm/provider.ts:85-131`），运行结束在 `done` 事件和 `/trace` 页展示 `prompt+completion`（`app/trace/[runId]/page.tsx:54-61`）。工具调用本身零 token——它们是本地函数。所以一次完整核对是千级 token 量级，且可关掉、可降级为零。

**Q21 我注意到这个问题是出血，可证据面板第一条是糖尿病文档，怎么说？**
您说得对，这是我们真实的短板。规则引擎的检索式把"问题 + 主诉 + 全部药名 + 全部诊断"一起拼进去（`runtime.ts:461`），王秀兰有 2 型糖尿病、在用二甲双胍，糖尿病文档就被药名带到了第一（实测 `logs/runs/run_7tv98tsan.json` 前三名都是 `kb-diabetes-basics`，得分 1.00 / 1.00 / 0.9478）。但请注意两点：一是高风险发现不会因此漏证据——证据锚定会用 `evidence` docId 定向补检（`runtime.ts:472-488`）；二是修复路径已经明确：把检索按发现拆开，一条发现一次检索。

**Q22 那你们凭什么说 Hit@1 0.714 算"够用"？**
我们不说够用，我们说"可度量、可改进"。14 条探针里 Hit@3 是 0.929，说明证据基本都在前三——对"结论要能引用"这个目标够用；但 Hit@1 只有 0.714，意味着排序还不够准，评委会看到第一条证据和直觉不一致，这是真实体验问题。所以下一步不是调参，而是改检索式构造和清理文档边界，指标会跟着涨，脚本可以再跑一次验证。

### 3.1 断网

- **现象**：页面正常，回答照常生成，徽标显示"规则引擎"。
- **根因**：所有推理走本地；知识库、药物库、规则库都是仓库内 JSON/Markdown（`lib/data.ts`、`lib/rag/index.ts:20`）；字体是系统字体栈（`tailwind.config.ts:41-54`），无远程字体。
- **话术**：「现在我把网络断掉——注意，回答没有变化。因为我们的检索、规则、工具全部在本机，外部模型只是"可选增强"，不是"依赖"。这就是我们敢在村卫生室部署的原因。」
- **动作**：`【断网】` → 再问一次 → 对比两次结果的结构一致性。

### 3.2 没有 API Key / Key 失效

- **现象**：`/evidence` 底部引擎行显示"本地规则引擎"；提问时右栏出现黄色 `note`："大模型规划失败（…），已自动降级到规则引擎，后续流程不受影响。"
- **根因**：`getLlmConfig().enabled = provider !== 'mock' && apiKey && baseUrl && model`（`lib/llm/provider.ts:62`）；规划与生成各有 try/catch 降级（`runtime.ts:421-442`、`506-542`）。
- **话术**：「这条黄条不是报错，是降级记录。我们故意把它显示出来——医疗 AI 必须告诉用户"我现在用的是哪条路径"。您看后面的 7 步、8 个工具、证据和守门，一条都没少。」
- **动作**：指着 `note` 黄条讲 5 秒，然后把轨迹面板往下滚，证明步骤数与有 Key 时一致。

### 3.3 模型超时 / 卡住

- **现象**：中间出现"正在规划与取证…"，超过十几秒没有 token。
- **根因**：流式请求在等首包；接口 `maxDuration = 60`（`app/api/chat/route.ts:15`），超时会走 catch 分支。
- **处置（按顺序）**：
  1. 先别动鼠标，口头解释：「这一轮在等模型首包，我们 60 秒兜底。」
  2. 若 20 秒无响应：`【动作】`停掉本次，改在输入框下方用规则引擎重跑同一问题——因为降级路径本身就是演示素材。
  3. 话术：「顺便展示一下我们的降级：同一句话，模型不可用时，规则引擎给出的是同结构答案，结论一致、证据一致。」
- **预防**：正式演示时把 `LLM_TEMPERATURE` 保持默认 0.2（`lib/llm/provider.ts:60`），不要临时换模型；提词只用脚本里的 4 条快捷问题（`ChatPanel.tsx:37-42`），它们都已被验证能触发完整链路。

### 3.4 SSE 被反向代理 / 中间层缓冲（现场用酒店 Wi-Fi 或别人电脑）

- **现象**：回答一次性"啪"地全部出现，轨迹面板最后才刷新；或浏览器一直转圈。
- **根因**：某些代理会缓冲 `text/event-stream`。项目侧已做两件事：响应头带 `X-Accel-Buffering: no` 与 `Cache-Control: no-store, no-transform`（`app/api/chat/route.ts:60-67`）。
- **处置**：
  1. 改用 `http://127.0.0.1:3000` 本机访问，不要走局域网 IP 或任何反代。
  2. 换浏览器（Chrome / Edge）。
  3. **话术（把故障变卖点）**：「流式被打断了正好说明一件事：我们的结果是可回放的。您看 `/safety` 里这次运行已经落盘，点"查看"进 `/trace`，刚才每一帧都在。」——`lib/agent/store.ts:17-29` 落盘，`/trace/[runId]` 回放。
- **兜底**：提前在本地跑 3 次并**不要清空** `logs/runs`，答辩时随时有一条完整轨迹可回放，不依赖现场网络。

### 3.5 浏览器不支持语音识别 / TTS

- **现象**：点麦克风后输入框出现"（当前浏览器不支持语音识别，请使用 Chrome 或 Edge）"。
- **根因**：代码主动判断 `SpeechRecognition ?? webkitSpeechRecognition`，不支持时给文案而不是报错（`components/console/ChatPanel.tsx:83-87`）。
- **话术**：「语音是渐进的增强，不是必需路径。我们用 Web Speech API 做了零依赖方案，不支持就降级为文字输入——这是我们对"适老化不等于加一个大喇叭"的理解。」
- **替代动作**：改点「朗读」（`speak()`，0.92 倍速，`ChatPanel.tsx:141-153`），或直接演示药盒拍照。

### 3.6 回答被安全守门改写（评委可能以为"答非所问"）

- **现象**：回答里出现"可能涉及"，或多出一段"> 涉及剂量的内容须由执业医师依据患者具体情况核定"；右栏出现"输出命中诊断性断言 / 剂量表述缺少证据引用"。
- **根因**：`guardOutput` 的规则（`lib/safety/index.ts:124-160`）：诊断断言、绝对化、弱化就医的表述会被替换为"可能涉及"；出现剂量单位却没有 `[n]` 引用时，追加医师核定提示。
- **话术（这是加分点，别慌）**：「这不是模型答错，是**第四道闸门在工作**。它在把"确诊"改成"可能涉及"，把没有引用的剂量加限定。医疗场景里，宁可让答案弱一点，也不能让它硬。您看右栏，每一次改写都有记录，也写进了审计。」
- **动作**：主动演示一次——输入「确诊是胃溃疡吗？直接把华法林停了吧」，让守门当场触发（README 第七节同款用例）。

### 3.7 评委翻到 `/safety` 问"为什么红旗症状了还写 ok"

> **该问题已在验证阶段自查并修复**（`docs/verify.md` 第 7.1 节）。现场看到的应是 `block`；若评委拿的是旧截图，按下面的话术答。

- **现象**：审计流水的"安全"列显示 `ok`，但同一行的"触发强转诊"统计却是 0，而右栏红旗标记明明已经出现。
- **根因（我们自己的缺陷，别遮掩）**：`lib/agent/runtime.ts` 落盘时把 `run.safety.level` 赋成了 `guarded.level`，也就是"输出守门"的等级，丢掉了输入侧红旗的 `block` 等级；UI 的红色横幅走的是 `forceReferral`，所以显示正常，但审计口径偏低。
- **已完成的修复**：改为 `finalLevel = max(输入等级, 输出等级)`（`ok < notice < block`）。修复后 `npm run audit:report` 输出 `安全等级：{ ok: 10, block: 3, notice: 2 }`，p-001 的出血提问稳定记为 `block`。
- **话术**：「这是我们验证阶段自己抓出来的一个统计口径 bug——红旗等级取了输出侧，把输入侧的 block 覆盖掉了。判断逻辑本身是对的（横幅、转诊单、强制就医都正常触发），错的是写进审计的那个字段。现在改成取两侧最大值，审计汇总里已经能看到 3 次 block。我们把它写在 `docs/verify.md` 里，因为**能被自己挑出问题的系统，才敢交给别人审计**。」
- **为什么这样答**：评委在这类追问上考的是"团队是否真的读得懂自己的代码"，能指出位置、说清根因、给出并验证修复，比硬解释更得分。
