> 比赛要求：5–8 分钟、MP4、分辨率不低于 1080p、普通话讲解，内容覆盖项目介绍、核心功能和 AI 技术亮点。

## 一、录制前准备

1. 使用 Chrome 或 Edge，窗口最大化，分辨率 1920×1080，缩放 100%。
2. 打开 `http://127.0.0.1:3000`，关闭书签栏、聊天软件通知和无关标签页。
3. 提前跑一次王秀兰用例，确认回答、引用和轨迹均能生成；保留最近 2–3 条审计记录。
4. 首页、诊台、依据页和安全审计页各预热一次，避免录制时首次编译。
5. 录制时使用脚本中的快捷问题，不临时输入新的医疗问题。
6. 所有患者均为合成演示数据，画面中不要出现 `.env.local`、终端密钥或个人信息。

## 三、逐镜头口播与操作

### 镜头 1｜0:00–0:35 项目介绍

**画面**：首页标题，缓慢滚动到问题场景区域。

**口播**：

> 基层老年患者常同时服用处方药、自购药和家属推荐的药。只有把药物、检验指标和新症状放在一起，组合风险才会显现。
>
> “守药人 MediGuardian”是一款基层用药安全 AI Web Agent。它不替医生诊断或开方，而是发现风险、查找依据，并把决策过程完整留痕。

**字幕**：处方药 + 自购药 + 检验 + 症状｜辅助判断，不替代医生

---

### 镜头 2｜0:35–1:00 三栏智能诊台

**操作**：点击“进入智能诊台”，依次指向左、中、右三栏。

**口播**：

> 诊台采用三栏结构：左侧是在吃什么，中间是说了什么，右侧是系统凭什么这样判断。
>
> 橙色代表非医嘱药，因为最容易遗漏的往往正是患者自己购买或别人推荐的药。

---

### 镜头 3｜1:00–2:35 核心用药安全流程

**操作**：

1. 选择“王秀兰，78 岁”。
2. 点击快捷问题：`最近牙龈出血、大便发黑，是不是止痛药引起的？`
3. 红色危险信号横幅出现后停 2 秒。
4. 展示右侧七步计划和工具卡；展开一次 `check_interaction`。
5. 回答完成后，点击正文中的一个引用编号。

**口播**：

> 现在输入：最近牙龈出血、大便发黑，是不是止痛药引起的？
>
> 系统先执行安全筛查。“黑便”和“牙龈出血”命中危险信号，红色横幅在回答前就已出现，回答必须把立即就医放在第一位。
>
> 右侧同时执行七步工作流：载入档案、核查相互作用、评估检验、检索证据、生成方案和转诊信息，最后经过输出守门。
>
> 工具层负责确定性判断，模型或本地模板负责组织表达。即使模型不可用，相互作用、红旗和检验分层也不会消失。
>
> 点击回答中的引用编号，右侧会定位到原文，并展示 BM25、词形向量、RRF 和术语重排分数。系统不仅给答案，也允许继续追问“为什么”。

**字幕**：输入先筛查｜七步 Agent｜确定性工具｜引用可跳转

---

### 镜头 4｜2:35–3:10 用药冲突图谱

**操作**：右侧切换到“冲突图谱”，点击华法林与布洛芬之间的红色连线。

**口播**：

> 这里是用药冲突图谱。药物是节点、相互作用是连线；红色表示高风险，橙色表示非医嘱药。
>
> 点击华法林和布洛芬的连线，可以看到机制、证据和动作。系统不会要求患者自行停掉处方抗凝药，而是提示立即就医并由接诊医生处置。

---

### 镜头 5｜3:10–4:05 RAG 与依据页

**操作**：进入“依据与规则”，展示检索消融表；在检索框输入 `三联打击 肌酐`，展开第一条结果，再滚动到来源状态说明。

**口播**：

> 第二个重点是可复现的 RAG。当前知识库包含十七篇文档、五十九个检索块。
>
> BM25、受限同义词和本地词形向量共同召回，再通过 RRF 与术语重排得到结果。输入“三联打击、肌酐”，可以直接看到分数构成。
>
> 六十三条自标注探针的 Hit@3 为 1.000、Recall@5 为 0.955。这些数字只用于工程回归，不代表临床准确率，具体建议仍需药师复核。

**字幕**：17 篇｜59 分块｜63 条检索探针｜工程指标不等于临床验证

---

### 镜头 6｜4:05–4:50 轨迹回放与安全审计

**操作**：返回回答，点击“决策轨迹”；展示最终模式、安全等级、工具耗时和证据。再进入“安全审计”。

**口播**：

> 每次运行都会生成可回放轨迹，包括步骤、工具、证据、安全标记和最终执行模式。
>
> 本轮最终模式显示为 LLM，模型完成规划和回答生成；相互作用、红旗筛查与安全守门仍由本地确定性工具完成。若网络或额度异常，系统会显示降级提示并切换到规则引擎，不会隐藏状态。
>
> 审计日志还使用前序哈希形成链式校验，修改中间记录就会被验证脚本发现。

**字幕**：LLM → 规则引擎｜透明降级｜轨迹可回放｜哈希链防篡改

---

### 镜头 7｜4:50–5:30 多模态与适老化

**操作**：点击大字模式；展示麦克风按钮和朗读按钮；打开图片上传入口，但不要把演示结果说成真实视觉准确率。

**口播**：

> 面向老年用户，我们提供语音输入、回答朗读和全站大字模式，播报时会自动移除 Markdown 和引用编号。
>
> 图片会在浏览器端重编码以移除元数据；识别结果必须经过药名归一化和人工确认，未匹配药不会静默进入核查。
>
> 当前 DeepSeek 是文本模型，系统会明确提示未配置视觉模型。仓库已准备三十六张开放许可鲁棒性样本，接入兼容模型后再报告准确率。

---

### 镜头 8｜5:30–6:10 AI 技术亮点总结

**画面**：在诊台右栏、依据页和首页技术标签之间快切。

**口播**：

> 守药人不是一次简单的大模型 API 调用。
>
> 上层是支持规划、多轮语境和工具调用的 Agent；中间是八个确定性工具和混合 RAG；底层是红旗、脱敏、证据覆盖和输出守门。相同工具还通过 MCP 对外暴露。
>
> 云端模型增强规划和表达，本地规则引擎保证断网或额度不足时仍然可用。这就是我们的双引擎设计。

---

### 镜头 9｜6:10–6:40 收束

**画面**：回到首页标题，缓慢滚动到项目价值区域。

**口播**：

> 守药人不是让 AI 替医生决定，而是让用药核查更完整、更透明、更容易追溯。
>
> 它帮助基层人员看见容易遗漏的自购药，让家属理解什么时候必须就医，也让结论能回到工具、规则和证据。
>
> 守药人，让用药风险被更早看见。谢谢各位老师。

## 四、真实 LLM 录制检查

本轮已通过上述条件，可使用真实 LLM 话术：`startedMode=llm`、`finalMode=llm`、无降级 note，最新一轮 3/3 通过。开始录制前仍建议跑一次 `npm run eval:llm`，避免额度或网络状态变化。

口播可用：

> 这一轮从自主规划到最终生成全部由已配置的大模型完成，右侧仍由本地工具负责相互作用和安全判断。轨迹中的最终模式为 LLM；如果模型调用失败，系统会切换到规则引擎并留下明确记录。

如果录制前复测出现 `fetch failed` 或最终模式为 `mock`，不要使用真实模型话术，切换为镜头 6 中的透明降级版本。

## 五、后期与导出检查

- 成片控制在 6 分 20 秒至 7 分钟，绝不能超过 8 分钟。
- 字幕字号不低于 28px，避开页面底部按钮和右侧轨迹区。
- 鼠标移动要慢；每次点击后停 1–2 秒，再开始口播。
- 高风险横幅、引用跳转、冲突图谱、轨迹页至少各保留 3 秒完整画面。
- 建议画面与配音分开录制，后期删除加载等待和鼠标寻找时间。
- 导出 H.264 MP4、1920×1080、30fps、码率 8–12 Mbps。
- 文件名：`学校-队伍名-守药人-演示视频.mp4`。
- 最终检查：没有 API Key、真实姓名、聊天通知、终端错误窗口或未授权素材出现在画面中。
